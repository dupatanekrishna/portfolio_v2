Incident case study

        ↓

        ↓

        ↓
pg_stat_activity shows PgSleep wait
        ↓

Recovery was validated using the same signals that detected the incident: application latency, metrics, traces and database activity.

Operational approach

Detect → Alert → Acknowledge → Investigate → Mitigate → Verify → RCA

The troubleshooting path is followed end to end rather than stopping at a single component:

DNS → CDN/WAF → ALB → target group → Service → EndpointSlice → Pod → App → RDS

Engineering outcomes

  • Correlate metrics, logs, traces and database evidence.
  • Diagnose latency and dependency failures methodically.
  • Reason about SLI/SLO/SLA, error budgets and alert quality.
  • Handle Terraform drift, imports and state recovery safely.
  • Troubleshoot Kubernetes networking and IAM access.
  • Plan secret/certificate rotation and recovery validation.
